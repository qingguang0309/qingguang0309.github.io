Featured work

Adapting and optimizing MiroFlow for Keen AgenticOS

I adapted the open-source MiroFlow research-agent framework for the KeenData team and optimized it around one idea: a hard question is usually lost at the final judgment, not in search.

Adjudicating-hub agent

Sub-agents gather evidence; the main agent keeps every defensible candidate alive and decides once, at the end. Like a Router–Worker design, but the hub's job is judgment, not just dispatch.

  1. Neutral orchestrationSub-tasks ask for data, never for a pre-chosen reading of the question.
  2. Evidence-first workersWorkers return verbatim quotes, sources and archived values, not conclusions.
  3. Terminal adjudicationCandidates are compared once, from the question-writer's point of view.
  4. Traceable verdictThe final answer is transcribed from the evidence, never re-solved.
  • Reliability engineering. A launch gate (API preflight, smoke run, trace check) and a run guard that keeps long evaluation runs safe.
  • Multi-model routing. Claude, GPT, Kimi and Gemini as interchangeable main models, with hardened audio, video and file-reading tools.
  • Deterministic output layer. Format checks and normalization, so a correct answer is never lost to formatting.
  • Benchmark integrity. Search and fetch filters that keep the agent away from leaked benchmark answers.
